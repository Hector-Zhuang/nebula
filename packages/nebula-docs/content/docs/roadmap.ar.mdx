تلخص هذه الصفحة الاتجاهات التقنية الأكثر وضوحًا في Nebula حاليًا. وهي تهدف إلى مساعدة فرق المضيف والمنصة على فهم أولويات Nebula القادمة، وليست وعدًا بموعد إصدار أو خطة تسليم نهائية.

ما نركز عليه ليس مجرد إضافة المزيد من واجهات API أو المزيد من قدرات الصفحات، بل جعل Nebula **منصة تطبيقات مصغّرة أكثر أمانًا، وأكثر قابلية للحوكمة، وأسهل في التشغيل، وأكثر قابلية للتوسعة**.

<Info title="نرحب بالملاحظات">
  إذا كانت لديك احتياجات محددة أو تقييم مختلف أو أفكار جديدة أثناء استخدام Nebula، فنحن نرحب بها.

  كثير من حدود Nebula ترتبط مباشرة بالواقع العملي للمضيف، وبنموذج الحوكمة، وبكيفية تعاون الفرق. ولهذا فإن ملاحظات المطورين ستؤثر مباشرة على القرارات القادمة.
</Info>

## الاتجاه الأول: عزل JavaScript

تخطط Nebula لإدخال آلية أكثر صرامة لعزل JavaScript، بهدف الحد من وصول التطبيقات المصغّرة مباشرة إلى أي وحدة أصلية يوفّرها وقت تشغيل المضيف.

وتشمل الأهداف:

- منع التطبيقات المصغّرة من تجاوز نظام Host API واستدعاء الوحدات الأصلية مباشرة
- تقليل خطر حزم npm التابعة لجهات خارجية التي تحاول الوصول إلى قدرات أصلية غير مصرح بها
- جعل سطح القدرات التي يوفّرها المضيف أوضح وأسهل للمراجعة
- توفير عزل أقوى لسيناريوهات تعدد المستأجرين، والبيئات المنظّمة، والمتطلبات العالية للامتثال

وسيؤثر هذا بشكل مباشر على حدود المنصة:
يجب أن تتفاعل التطبيقات المصغّرة مع المضيف عبر واجهات Nebula العامة، لا أن تتعامل مع وقت تشغيل المضيف كبيئة أصلية مفتوحة.

## الاتجاه الثاني: خادم MCP

تخطط Nebula لتوفير قدرات MCP server، بحيث تتمكن النماذج، وأدوات الأتمتة، وسير العمل التطويري من فهم سياق المضيف والتطبيق المصغّر وواجهة API الحالية بشكل أفضل.

وقد يشمل ذلك:

- كشف بيانات التطبيق المصغّر، وبنية الصفحات، والإعدادات
- كشف معلومات Host APIs المسجلة
- كشف العلاقة بين المكونات والقدرات والتوافق بين الإصدارات
- توفير نقطة دخول موحّدة لأدوات التطوير والتشخيص والأتمتة

وسيسهّل ذلك دمج Nebula مع:

- التطوير المدعوم بالذكاء الاصطناعي
- الفحوص الآلية
- اكتشاف قدرات المضيف
- سلاسل الأدوات المشتركة بين الفرق

## الاتجاه الثالث: أتمتة الوثائق

ستواصل Nebula الاستثمار في أتمتة الوثائق، لتقليل الانجراف بين الكود الفعلي والوثائق الخاصة بالواجهات والمكونات وقدرات المضيف.

وتشمل الاتجاهات الرئيسية:

- استخراج أوصاف منظّمة من تعريفات API
- توليد وثائق reference أو التحقق منها تلقائيًا
- اكتشاف الأمثلة الناقصة أو أوصاف الحقول أو تفاصيل التوافق المفقودة
- توحيد Host APIs ومكتبة المكونات وقدرات المنصة في مصدر وثائق قابل للاستهلاك الآلي

ولهذا السبب تظهر أحيانًا حقول بيانات وصفية مثل `description` في بعض تعريفات القدرات.
فهذه الحقول لا تخدم القراءة البشرية فقط، بل تدعم أيضًا أتمتة الوثائق، واكتشاف القدرات، والتكامل مع الأدوات.

## الاتجاه الرابع: الهوية البصرية

ستعمل Nebula تدريجيًا على تحسين قدرات التخصيص والعلامة البصرية، حتى تتمكن الفرق المختلفة من بناء تجربة مضيف وتجربة تطوير أقرب إلى هوية منتجاتها.

وقد يشمل ذلك:

- واجهات Dev Runner وتجارب إطلاق قابلة للعلامة البصرية
- تخصيص الحاوية، وصفحات التحميل، وصفحات الخطأ، وحالات الفراغ في المضيف
- تخصيص أدلة التطبيقات المصغّرة ونقاط الدخول وصفحات التوزيع والتشغيل
- قدرات بصرية في وقت التشغيل تتماشى بشكل أفضل مع نظام التصميم الخاص بالمضيف

الهدف ليس مجرد تغيير المظهر، بل تمكين المضيفين المختلفين من الحفاظ على هويتهم الخاصة فوق أساس تقني موحّد.

## الاتجاه الخامس: حواجز API على جانب المضيف

ستعمل Nebula على تقوية آليات الحراسة الخاصة بواجهات API على جانب المضيف، حتى يتمكن المضيف من التحكم بدقة أكبر في:

- أي الواجهات يتم كشفها
- أي الواجهات لا تظهر إلا في نسخ معينة من المضيف
- أي الواجهات تحتاج إلى أذونات إضافية أو تحقق من السياق
- أي الواجهات يجب منعها في مستأجرين أو مستخدمين أو سيناريوهات معينة

وقد تغطي هذه الآليات:

- التحكم الثابت في مرحلة تسجيل القدرات
- التحقق من المعاملات واعتراض الاستدعاءات أثناء التشغيل
- الربط بين الواجهة وسياق الهوية أو الأذونات
- نتائج خطأ أوضح وسجلات تدقيق أكثر اكتمالًا

وستتكامل هذه الطبقة مع عزل JavaScript ونظام Host API وآليات الامتثال لتشكيل طبقة حماية أكثر تكاملًا للمنصة.

## الخلاصة

الوجهة القادمة لـ Nebula ليست تحويلها إلى نظام أكثر حرية لتوزيع الكود الديناميكي، بل تطويرها إلى **منصة تطبيقات مصغّرة أكثر قابلية للتحكم، وأكثر أمانًا، وأكثر قابلية للحوكمة**.

وانطلاقًا من هذا الهدف، ستركز المراحل القادمة على:

- عزل أقوى في وقت التشغيل
- حدود أوضح لقدرات المضيف
- تكامل أفضل مع الأتمتة والأدوات
- دعم أكثر اكتمالًا للعلامة البصرية
- حوكمة وحراسة أكثر صرامة لواجهات API

إذا كنت تخطط لبناء منصة مضيف، أو نظام امتثال، أو منظومة تطبيقات مصغّرة داخلية فوق Nebula، فهذه الاتجاهات تستحق أولوية أعلى من مجرد إضافة المزيد من واجهات الأعمال.
