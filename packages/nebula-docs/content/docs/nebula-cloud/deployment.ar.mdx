Nebula Cloud هو **تنفيذ مرجعي** ويوفّر الحد الأدنى فقط من إدارة المستخدمين والإصدارات. في بيئات الإنتاج، ينبغي عليك توسيعه أو بناء خدمة خلفية خاصة بك. وفي كلتا الحالتين، يجب أن تطبق خدمتك الواجهات المطلوبة وقت التشغيل المحددة في [Nebula Cloud API](/docs/reference/nebula-cloud-api)، وإلا لن يتمكن Nebula runtime من تنزيل التطبيقات المصغّرة وتثبيتها.
</Callout>

## ما الذي يوفّره Nebula Cloud

Nebula Cloud مبني على NestJS وPrisma ويشمل القدرات الأساسية التالية:

| الميزة | الوصف |
|------|------|
| تسجيل المستخدمين وتسجيل الدخول | مصادقة البريد وكلمة المرور و JWT |
| تفويض أجهزة CLI | OAuth device flow لـ `nebula auth login` |
| تسجيل التطبيقات المصغّرة | إنشاء التطبيقات وإدارة البيانات الوصفية |
| رفع الإصدارات | استقبال bundle و manifest من CLI |
| إدارة حالات الإصدارات | تدفق DRAFT → SUBMITTED → APPROVED → PUBLISHED |
| النشر عبر القنوات | فصل قنوات test / stable |
| توزيع الحزم | واجهات تنزيل يستخدمها runtime |

### ما الذي لا يوفّره Nebula Cloud

- توزيع عبر CDN
- مراجعة آلية
- صلاحيات فرق
- مراقبة وتحليلات
- تصفية المحتوى
- نشر تدريجي
- Webhook / إشعارات
- دعم متعدد المستأجرين

## نشر Nebula Cloud

### المتطلبات

- Node.js 18+
- PostgreSQL أو أي قاعدة بيانات يدعمها Prisma

### تشغيل الخدمة

```bash
cd packages/nebula-cloud
npm install
npx prisma migrate deploy
npm run start
```

بشكل افتراضي، تستمع الخدمة على المنفذ `3001` وتعرض واجهاتها تحت `/api`.

## بناء خدمة خلفية مخصصة

إذا لم يناسبك التنفيذ المرجعي، يمكنك بناء خدمة خلفية خاصة بك بأي تقنية. الشرط الأساسي هو تنفيذ الواجهات الحرجة لوقت التشغيل المحددة في [Nebula Cloud API](/docs/reference/nebula-cloud-api).

## إدارة الإصدارات

### مسار حالات الإصدار

```text
DRAFT -> SUBMITTED -> APPROVED -> PUBLISHED
				  -> REJECTED
```

| الحالة | الوصف |
|------|------|
| `DRAFT` | الحالة الأولية بعد الرفع |
| `SUBMITTED` | تم الإرسال للمراجعة |
| `APPROVED` | تمت الموافقة |
| `REJECTED` | تم الرفض |
| `PUBLISHED` | تم النشر |
