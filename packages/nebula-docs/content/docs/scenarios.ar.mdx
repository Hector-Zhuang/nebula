تناسب Nebula الحالات التي يحتاج فيها تطبيق مضيف واحد إلى تشغيل عدة وحدات أعمال مستقلة. يتم تطوير كل وحدة ونشرها وتحديثها كـ miniapp مستقلة، من دون انتظار إصدار جديد لتطبيق المضيف.

## السيناريو الأول: التطبيق الفائق

في السياق العربي، من الأنسب تشبيه هذا النموذج بـ **تطبيقات شبيهة بـ Careem Super App**:

```
Careem (تطبيق مضيف)
├── Careem Pay        ← miniapp
├── دفع الفواتير      ← miniapp
├── طلب سيارة         ← miniapp
├── توصيل الطعام      ← miniapp
├── خدمات السفر       ← miniapp
└── ...العديد من miniapps الخدمية
```

**الاحتياجات الأساسية:**

- يوفّر المضيف نقطة دخول موحدة وقدرات مشتركة مثل الدفع والموقع وتسجيل الدخول
- تستطيع كل جهة أعمال التطوير والإصدار بشكل مستقل
- يتحكم المضيف في الصلاحيات وحدود القدرات
- لا يحتاج المستخدم إلى تثبيت عدة تطبيقات

**كيف تساعد Nebula:**

| الحاجة | أسلوب Nebula |
|------|-------------|
| واجهات قدرات موحدة | آلية تسجيل Host API تتيح للمضيف تعريف واجهات موحدة |
| إصدار مستقل | تدير Nebula Cloud الإصدارات ورفع الـ miniapp بشكل مستقل |
| عزل أمني | عزل sandbox يمنع مشاركة الملفات والتخزين بين الـ miniapps |
| تشغيل سريع | التحميل المسبق يقلل تأخير الإقلاع البارد |

## السيناريو الثاني: منصة مؤسسية داخلية

تخيّل منصة داخلية كبيرة تضم عدة أنظمة أعمال:

```
المنصة المؤسسية (تطبيق مضيف)
├── المستودعات       ← miniapp
├── التدقيق          ← miniapp
├── CRM المبيعات     ← miniapp
├── الموارد البشرية  ← miniapp
├── المصروفات        ← miniapp
└── الفحص الميداني   ← miniapp
```

**الاحتياجات الأساسية:**

- كل فريق يطوّر وحدته بشكل مستقل
- يستخدم الموظفون تطبيقًا واحدًا كنقطة دخول موحدة
- يوفّر المضيف قدرات مشتركة مثل المسح والكاميرا والموقع
- تدعم الوحدات الإطلاق التدريجي والإصلاح السريع
- تبقى بيانات كل وحدة معزولة

**كيف تساعد Nebula:**

| الحاجة | أسلوب Nebula |
|------|-------------|
| تطوير مستقل | لكل وحدة مستودع وبناء ورفع مستقل |
| قدرات جهاز مشتركة | يوفّر المضيف القدرات الأصلية عبر Host APIs |
| فصل الاختبار عن الإطلاق | يمكن رفع النسخ كتجربة قبل الإصدار النهائي |
| إصلاحات سريعة | يمكن لسياسات التحديث اكتشاف الإصدارات الجديدة وتطبيقها |
| عزل البيانات | لكل miniapp تخزين ونظام ملفات معزولان |

## السيناريو الثالث: تطبيقات مولّدة بالذكاء الاصطناعي

يمكن للمستخدم وصف التطبيق بلغة طبيعية، ويقوم Chatbot بإنشاء miniapp ونشرها:

```
المستخدم: "أنشئ تطبيقًا للجرد يدعم الإدخال بالمسح والتصدير إلى Excel"

Chatbot:
  1. يولّد صفحات React Native
  2. يشغّل nebula miniapp build
  3. يشغّل nebula miniapp upload إلى Nebula Cloud
  4. يسمح للمضيف باكتشاف الـ miniapp الجديدة وتحميلها

يفتح المستخدم التطبيق المضيف → التطبيق الجديد جاهز
```

**الاحتياجات الأساسية:**

- يجب أن يتحول الكود المولّد مباشرة إلى miniapp قابلة للتشغيل
- يجب أتمتة سلسلة الإنشاء ثم البناء ثم النشر
- يجب أن يحمّل المضيف الـ miniapp الجديدة من دون إعادة بناء نفسه
- يجب أن تتمكن التطبيقات المولّدة من استخدام القدرات الأصلية
- يجب أن يبقى التكرار سريعًا عبر الحوار والرفع المتكرر

**كيف تساعد Nebula:**

| الحاجة | أسلوب Nebula |
|------|-------------|
| مخرجات قياسية | تستخدم الـ miniapps React + TypeScript بما يناسب توليد LLM |
| نشر آلي | يوفّر CLI أوامر `build` و`upload` القابلة للبرمجة |
| عدم الحاجة لإصدار جديد | يستطيع المضيف تثبيت الـ bundles عبر OTA |
| قدرات أصلية | تتيح Host APIs المسح ونظام الملفات والموقع وغير ذلك |
| تحديثات متكررة | تدير Nebula Cloud الإصدارات والنسخ الجديدة |
| حدود أمان | يحافظ sandbox على عزل الكود المولّد |

## لماذا ليس WebView؟

Nebula ليست مجرد غلاف متصفح:

| البعد | WebView | Nebula |
|--------|---------|--------|
| العرض | عرض ويب | عرض React Native |
| الأداء | محدود بمحرك المتصفح | قريب من الأداء الأصلي |
| قدرات الجهاز | تحتاج إلى JSBridge مخصص | واجهات Host API موحدة |
| نموذج الصفحات | تطبيق أحادي الصفحة أو iframe | مكدس صفحات أصلي مع تحميل مسبق |
| دورة الحياة | أحداث عامة | دورة حياة دقيقة مثل `onShow` و`onHide` |
| العمل دون اتصال | محدود | bundle محلي مع دعم أوفلاين |

## لماذا لا نضع كل شيء داخل المضيف؟

وضع كل منطق الأعمال داخل تطبيق المضيف يؤدي إلى:

- **ترابط في الإصدارات:** أي تعديل يحتاج إلى إصدار جديد للمضيف
- **تضخم الكود:** تكبر حزمة التطبيق مع كل وحدة جديدة
- **تعطّل الفرق:** عدة فرق داخل مستودع واحد تزيد تكلفة التنسيق
- **صعوبة الاسترجاع:** لا يمكن التراجع عن وحدة واحدة بسهولة

تفصل Nebula وحدات الأعمال عبر نموذج miniapp: مستودعات مستقلة، وبناء مستقل، وإصدار مستقل، وتراجع مستقل، بينما يركز المضيف على الحاوية والقدرات المشتركة.
